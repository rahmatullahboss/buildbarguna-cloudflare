## 2024-06-02 - Unescaped User Input in HTML-to-PDF Conversion
**Vulnerability:** The external API HTML-to-PDF generation service directly embedded user input into raw HTML string templates. Variables such as `reg.name_english`, `reg.form_number`, and `cert.user_name` were concatenated directly, exposing the system to Server-Side XSS and potentially SSRF vulnerabilities if the external PDF API evaluated the scripts in a headless browser environment that had access to sensitive endpoints.
**Learning:** Even when the primary output format is an external PDF rendering engine, HTML generated on the server is highly susceptible to injection if user data is placed unescaped into HTML templates. We must ensure robust HTML escaping in string interpolation workflows where a template engine is not being used to handle the encoding automatically.
**Prevention:** Strictly enforce the use of an `escapeHTML` function or a sanitized templating system for any HTML templates that handle user input, even for out-of-band processing (like PDF conversion).
